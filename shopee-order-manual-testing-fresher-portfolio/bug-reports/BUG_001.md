# [BUG_001] Inline validation error missing when submitting empty or invalid Citizen ID for cross-border items

- **Project**: Shopee Order & Checkout Flow
- **Reported By**: QA / Fresher Tester
- **Date Reported**: 2026-09-07
- **Environment**: 
  - Platform: Android Mobile App & Web Chrome (v128.0)
  - Device: Samsung Galaxy S23 (Android 14) / Windows 11 PC
  - App Build: `v3.14.0-rc3`
- **Severity**: **Major**
- **Priority**: **High (P1)**
- **Status**: **Open**
- **Associated Test Case**: [`TC_10`](../test-cases/Test_Cases_Specification.md)
- **Component**: `Checkout > Shipping Address & Personal Information`

---

### Description
When ordering cross-border products requiring personal customs clearance identification, tapping "ID Card Information" and submitting an invalid ID number (less than 12 digits or special characters) or leaving the field completely blank fails to display an explicit inline error message. The screen simply remains static without informing the user what went wrong, leading to high cart abandonment rates and potential customs declaration rejections.

---

### Preconditions
1. User account is logged in.
2. Cart contains at least 1 cross-border item flagged with `requires_customs_id = true`.
3. User has progressed to the Checkout page.

---

### Steps to Reproduce
1. On Checkout page, scroll to the **Personal Information / ID Card Information** section.
2. Tap on the ID input field.
3. Enter an invalid ID string: `12345` (5 numeric digits instead of standard 12-digit CCCD).
4. Click the **Confirm / Save** button.
5. Observe the UI response.

---

### Expected Result
1. The input field border turns red (`#EF4444`).
2. A clear, localized inline error message appears below the field:  
   *`"Số CCCD/CMND không hợp lệ. Vui lòng nhập đúng 12 chữ số để thông quan."`*
3. The user is prevented from proceeding until a valid 12-digit CCCD is supplied.

---

### Actual Result
1. The modal closes or remains unresponsive without displaying any error banner or inline helper text.
2. The field remains populated with `12345`.
3. If the user clicks "Place Order", the backend API returns `422 Unprocessable Entity` with error code `ERR_INVALID_CUSTOMS_ID`, but the frontend UI does not translate this into a visible user alert.

---

### Console / API Logs
```json
POST /api/v4/checkout/validate_customs_id
Status: 422 Unprocessable Entity
Payload: {"user_id": 9812401, "id_type": "CCCD", "id_number": "12345"}
Response:
{
  "error": "ERR_INVALID_CUSTOMS_ID",
  "message": "Identification number must be exactly 12 numeric digits.",
  "field": "id_number"
}
```

---

### Impact & Workaround
- **Business Impact**: Cross-border orders submitted with unverified identification are rejected by customs logistics partners, leading to shipping failures, refund disputes, and legal non-compliance.
- **Workaround**: None on mobile app. Users must go to Web Profile settings and save their ID manually before attempting checkout.
